## 📖 项目简介

FitLink 是一款基于微信小程序的运动组局平台，帮助用户发现附近的运动活动、组建运动队伍。系统采用 **LBS 地理位置服务** 结合 **五维加权智能推荐算法**，为每位用户个性化推荐最合适的运动组局。

### ✨ 核心亮点

- 🧠 **五维智能推荐算法** — 综合运动偏好、时间紧迫度、地理距离、名额充裕度、用户活跃度
- 📍 **LBS 附近组局** — 基于 Haversine 公式的精确距离计算 + 地图/列表双视图
- 🏅 **信誉分系统** — 量化用户可信度，驱动推荐权重和组局排序
- 💬 **实时互动** — 评论、回复、点赞、收藏、微信消息推送
- 🎨 **Premium UI 设计** — 玻璃质感、微动效、弹性回弹、骨架屏加载

## 🧠 智能推荐算法（核心）

### 算法概述

FitLink 的推荐算法是一个 **五维加权综合评分系统**，每次用户请求附近组局时，系统会对候选组局逐一评分，按最终得分降序排列推荐。算法核心设计思想：

> **让低活跃用户快速找到"临门一脚"的机会，让高活跃用户享受充裕的选择空间。**

### 五维评分模型

#### 维度 1：运动偏好匹配（乘数权重 ×1.5）

```
用户偏好 = ["basketball", "running"]
组局运动 = "basketball"  → prefMultiplier = 1.5 ✅
组局运动 = "tennis"      → prefMultiplier = 1.0
```

- **设计思路**：偏好匹配采用乘数而非加法，确保匹配的组局始终排在非匹配组局之前
- 用户在「我的」页面设定运动偏好，偏好运动会排在筛选栏前面

#### 维度 2：时间紧迫度（-0.5 ~ +1.0）

```
得分分布：
  0~4 小时内  → 1.0 ~ 0.4（指数衰减）     ⬅️ 最高紧迫度
  4~24 小时   → 0.4 ~ 0.1（指数衰减）
  1~7 天      → 0.15 ~ 0.01（慢衰减）
  已过期       → -0.5（惩罚）               ⬅️ 大幅降权
```

- **分段函数设计**：使用不同衰减系数模拟人类对"即将到来"事件的紧迫感知
- 已过期组局会被大幅降权而非直接过滤，避免列表过短

#### 维度 3：地理距离（0 ~ 1.0，对数衰减）

```javascript
distScore = max(0, 1 - log(1 + distKm) / log(21))
//  0km → 1.0    1km → 0.73    3km → 0.55
//  5km → 0.43   10km → 0.26   20km → 0
```

- **Haversine 公式**计算球面距离，精度在城市尺度完全够用
- **对数衰减**：近处区分度高（1km 和 3km 差异明显），远处差异被压缩（15km 和 20km 差异很小）
- 距离超过搜索半径的组局会被直接过滤，不进入评分阶段

#### 维度 4：剩余名额充裕度（0 ~ 0.15）

```
spotsBonus = (spotsLeft / maxMembers) × 0.15
// 10 人组局剩 5 人 → 0.075
// 10 人组局剩 1 人 → 0.015
// 已满员 → 0
```

- 名额充裕的组局给予微小加分，但权重较轻
- 已满员组局自动触发招募结束，不会出现在推荐中

#### 维度 5：活跃度匹配（0 ~ 1.0）⭐

这是算法最核心的创新维度。系统将用户分为四个活跃等级，并采用**差异化推荐策略**：

| 活跃等级 | 判定条件 | 推荐策略 |
|---------|---------|---------|
| **high** | 7天内活跃 + 30天参加≥2次 | 充足空间 — 余位充足、有准备时间的队伍 |
| **mid** | 7~14天内活跃 | 平衡策略 — 适中余位和时间 |
| **low** | 14~30天内活跃 | 临门一脚 — 快满的、即将开始的队伍 |
| **dormant** | 超过30天未活跃 | 临门一脚 + 高信用队长加分 |

**差异化策略详情：**

```
低活跃/沉睡用户 → "临门一脚"策略：
  ├── 剩余1人 → +0.25（"就差你了！"）
  ├── 剩余2人 → +0.15
  ├── 12小时内开始 → +0.20（"马上就开打！"）
  ├── 12~24小时开始 → +0.10
  └── 队长信用≥120 → +0.05（降低信任顾虑）

高活跃用户 → "充足空间"策略：
  ├── 余位3~(max-1)人 → +0.15（不用抢位）
  ├── 12~72小时后开始 → +0.10（有准备时间）
  └── 6小时内创建的新组局 → +0.10（尝鲜新局）
```

**设计哲学**：低活跃用户回归时，降低其决策门槛（快满的队伍更容易触发"再不参加就没了"的紧迫感）；高活跃用户则推荐有充足余位的队伍，避免频繁遇到满员挫折。

### 最终综合公式

```javascript
score = (base + timeBonus + distScore + spotsBonus + activeMatch × 0.3) × prefMultiplier

// 其中：
//   base        = 0.5（基准分，确保所有组局得分>0）
//   timeBonus   = -0.5 ~ +1.0
//   distScore   = 0 ~ 1.0
//   spotsBonus  = 0 ~ 0.15
//   activeMatch = 0 ~ 1.0（× 0.3 权重）
//   prefMultiplier = 1.0 或 1.5
//
// 理论得分范围：0 ~ 2.65
```

### 信誉分系统

信誉分是推荐算法的间接影响力因素，通过影响队长可信度来间接影响组局质量：

| 行为 | 分值变化 | 说明 |
|------|---------|------|
| 创建组局并正常结束 | 队长 **+2** | 鼓励负责任的组局发起 |
| 参加组局并正常结束 | 队员 **+1** | 鼓励履约参与 |
| 被举报确认违规 | **-5** | 惩罚不良行为 |

- 分值范围：0 ~ 200，初始 100
- 高信用队长发起的组局在活跃度匹配中获得额外加分

## 🚀 快速开始

### 环境要求

- **Node.js** >= 18
- **微信开发者工具**（最新稳定版）
- **微信小程序 AppID**（已开通云开发）

### 1. 克隆项目

```bash
git clone https://github.com/yydscq6/FitLink.git
cd FitLink
```

### 2. 后端启动

```bash
cd server
cp .env.example .env   # 配置环境变量
npm install
node app.js            # 启动 Express 服务（默认 3000 端口）
```

### 3. 小程序端

1. 用微信开发者工具打开项目根目录
2. 在 `project.config.json` 中填入你的 AppID
3. 开通云开发环境
4. 上传 `cloudfunctions/api` 云函数并部署
5. 编译运行

### 环境变量配置（.env）

```env
# 必填
JWT_SECRET=your-strong-secret-here-min16
WX_APPID=wx1234567890abcdef
WX_SECRET=your_wx_secret_here

# 可选
PORT=3000
NODE_ENV=development
CORS_ORIGINS=*
```
